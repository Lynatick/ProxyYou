# Обновления ProxyYou через GitHub Releases

Оценка на 10 октября 2026 года. Обновление возможно на macOS, Android и Windows. Это проект решения: работающий установщик обновлений пока не внедрён, релизы не опубликованы.

## Что уже есть в исходниках

- `lib/core/model/constants.dart`: проверка обновлений отключена (`allowAppUpdates = false`); GitHub API и appcast указывают на Hiddify, а не ProxyYou.
- `lib/features/app_update/data/app_update_repository.dart`: получение списка релизов и разбор версии. Модель не содержит установочных файлов, архитектуры и контрольной суммы.
- Диалог новой версии открывает страницу релиза. Он не скачивает и не устанавливает обновление.
- `.github/workflows/proxyyou-build.yml`: ручная сборка Android и macOS с сохранением CI-артефактов. Публикации GitHub Releases и задания Windows нет.
- Общий скрипт CI скачивает готовое ядро Hiddify. Перед публикацией нужно обеспечить сборку с нашими патчами, иначе потеряются изменения ядра ProxyYou.

## Общий механизм

Использовать собственный публичный репозиторий ProxyYou и стабильные релизы. Приложение проверяет обновления в фоне при запуске с ограничением частоты и по кнопке «Проверить обновления». Проверка не должна перезапускать ядро, изменять системный прокси или зависеть от переключения фокуса.

Релиз содержит подписанный манифест: платформа, архитектура, версия, номер сборки, минимальная версия ОС, URL файла, размер и SHA-256. В приложение встроен только открытый ключ проверки подписи. GitHub-токен и закрытые ключи в приложение не включаются. SHA-256 проверяет целостность; подпись манифеста подтверждает источник обновления.

Выбирать только совместимый файл и сравнивать версию вместе с номером сборки. Не предлагать обновление платформы, если для неё нет более новой сборки: сейчас macOS имеет 4.1.16, Android и Windows — 4.1.17. Не устанавливать prerelease по умолчанию. Отсутствие сети и ошибки проверки не должны мешать подключению.

Файл скачивается во временную папку с прогрессом и отменой. Установка начинается после проверки размера, суммы и подписи, по нажатию «Установить». До замены программы сохранить данные, штатно отключить VPN/прокси и завершить ядро. Подписки и настройки остаются вне каталога заменяемых файлов. Совместимость базы данных проверяется отдельно; сохранение файлов само по себе не гарантирует совместимость новой версии.

## Платформы

| Платформа | Предлагаемая установка | Условия |
| --- | --- | --- |
| macOS | Sparkle 2: подписанный appcast, ZIP приложения, установка с перезапуском | Подпись обновлений EdDSA; для удобного публичного распространения Developer ID и notarization. У текущей сборки подпись ad hoc. Пока имеется только сборка Apple Silicon: Intel нельзя предлагать этот ZIP. |
| Android / Android TV | Скачать совместимый APK и передать системному PackageInstaller | Разрешение установки из этого источника и системное подтверждение. Сохранить package ID, увеличить versionCode и обеспечить совместимую подпись. Для обычного приложения первый вариант реализации предусматривает подтверждение каждой установки. |
| Windows x64 | Скачать существующий установщик Inno Setup EXE, штатно закрыть приложение, запустить установщик | Сохранить AppId и каталог установки. Имеющийся установщик устанавливается для текущего пользователя; отдельный ZIP не требуется. Проверка подписи пакета перед запуском обязательна в предлагаемой схеме; Authenticode полезна для публичного распространения. |

Android сейчас собран с тестовым Android Debug сертификатом. Нельзя просто подписать следующий APK новым ключом и считать его обновлением установленного приложения. До публичных релизов нужно определить постоянный ключ и способ перехода с текущей подписи; отдельно проверить возможность миграции подписи на поддерживаемых версиях Android. Не публиковать debug keystore в репозитории.

На macOS обновление означает полное завершение старого процесса. После запуска новой версии сетевое разрешение запрашивается один раз на новую сессию, как требуется текущим поведением приложения.

## Доставка и проверка

1. Определить репозиторий, постоянные ключи и соглашение об именах файлов.
2. Добавить Windows в CI и воспроизводимую сборку наших нативных ядер. Ключи хранить вне исходников; публикацию выполнять отдельным заданием после успешных проверок.
3. Публиковать релиз по тегу с APK, macOS ZIP, Windows Setup EXE, подписанным манифестом и appcast для Sparkle. Не помечать релиз доступным до загрузки всех заявленных файлов.
4. Добавить общий Flutter интерфейс проверки и скачивания, затем платформенные установщики.
5. Проверить обновление с предыдущей версии с сохранением подписок, отказ пользователя, повреждённый пакет, неподходящую архитектуру, недоступность GitHub, корректное восстановление системного прокси и перезапуск приложения. Android TV: пройти весь сценарий пультом.

Репозиторий исходников и релизов: https://github.com/lynatick/proxyyou. Репозиторий тестовых подписок используется только как источник тестовых данных.

## Уведомления начиная с 4.1.19

`allowUpdateNotifications = true`: фоновая проверка релизов GitHub при запуске, возвращении к приложению и периодически в активном приложении. Успешный результат кешируется на 6 часов, после ошибки повтор допускается через 15 минут; параллельные обращения объединяются. Ручная проверка в «О приложении» обходится без кеша. Баннер на главной появляется только для более новой стабильной версии с пакетом текущей платформы. Автоматической установки нет: `allowAppUpdates = false`.
