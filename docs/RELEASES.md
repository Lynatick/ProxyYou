# Выпуск обновлений

Источник релизов: https://github.com/Lynatick/proxyyou/releases.

Репозиторий подготовлен для исходников и релизов. Установщик обновлений пока не реализован; `allowAppUpdates` остаётся `false`. `appcast.xml` нужно добавить после интеграции Sparkle и настройки подписи, а не заменять пустым рабочим каналом.

## Порядок выпуска

1. Пройти workflow Validate ProxyYou и собрать приложения с модифицированным нативным ядром. Старый общий `scripts/build-proxyyou.sh` скачивает upstream-ядро: его нельзя использовать для выпуска текущего ProxyYou без доработки.
2. Собрать macOS через `scripts/build-macos-core.sh`, Windows через `scripts/build-windows-core.sh` и `scripts/build-windows.ps1 -InstallerOnly`. Android должен использовать AAR с патчем `native-patches/youtube-monitoring.patch`. Автоматическая сборка всех трёх платформ и подпись ещё требуют отдельной настройки.
3. После успешной проверки текущего main запустить Actions → Release ProxyYou с версией, например `v4.1.18`, и операцией `prepare`. Workflow создаст тег и черновик на этом коммите. Не создавать тег 4.1.17 на новом коммите только с изменёнными ссылками: ранее собранные пакеты не содержат этих изменений.
4. Загрузить APK, ZIP приложения macOS Apple Silicon и единственный Windows x64 Setup EXE, а также SHA256SUMS.txt. Версия каждого файла должна соответствовать его реальной сборке. Intel macOS пока не поддержан сборкой.
5. После внедрения обновлений дополнительно загрузить подписанный манифест и appcast. Перед публикацией проверить подписи, контрольные суммы и обновление установленной предыдущей версии с сохранением данных.
6. Запустить тот же workflow с операцией `publish`, подтвердив проверку файлов и раскрытие статуса подписей. Он проверит соответствие тега текущему проверенному коммиту, наличие трёх пакетов и их SHA-256, затем опубликует релиз. Проверка подписей и содержимого пакетов выполняется ответственным за выпуск; workflow сам их не проверяет. Не публиковать релизы через веб-интерфейс: исходная лицензия требует GitHub Actions.

## Подпись и настройки

GitHub Actions по умолчанию имеет только чтение репозитория. Для будущей публикации `contents: write` назначается только заданию выпуска. Закрытые ключи хранятся в GitHub Secrets или вне CI; никаких пользовательских PAT внутри приложения.

Текущая Android-сборка подписана Android Debug сертификатом: постоянный ключ и миграцию необходимо определить до публичных обновлений. macOS сейчас имеет подпись ad hoc: для публичного канала нужны подпись Sparkle и желательно Developer ID / notarization.

План платформенных установщиков: [GITHUB_UPDATES.md](GITHUB_UPDATES.md).
